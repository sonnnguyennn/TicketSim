## One checkpoint and qualification

For each VM-changing action, the operator supplies a unique request ID and exact approval text. Example syntax after that action has been separately approved:

```powershell
pwsh -NoProfile -NonInteractive -File scripts/real-lab/Invoke-FastReset.ps1 -Action checkpoint -RequestId b5-checkpoint-0001 -Apply -Approval 'APPROVE B5 checkpoint b5-checkpoint-0001'
```

The script creates at most one `ticketsim-lab-b5-clean-baseline-v1` checkpoint on the original Off VM. Record its **actual** ID, type, creation time, storage and VHD parent chain. It leaves an exclusive operator lease and an append-only journal in `E:\TicketSimOperatorState\b5`. A cmdlet return is not a qualification result. After independently checking the action, prepare a JSON evidence file with `RequestId`, `Action`, `VmId`, `CheckpointId`, `Verified:true`, `NoOtherVmChanged:true`, and `BackupUnchanged:true`. Only then run `Resolve-FastReset.ps1` with the exact request, checkpoint and `-Approval 'APPROVE B5 reconcile <requestId>'`. It rechecks host IDs, checkpoint, VM state and all four backup hashes before releasing that one operator lease. Do not reconcile a failed or uncertain action.

For the **separately approved** reset qualification, use distinct `start`, `stop`, `reset`, `start` requests, each with a new request ID, `-CheckpointId <actual-guid>`, exact `APPROVE B5 <action> <requestId>` approval text, and independent reconciliation between requests. `start` is blocked while the recovery VM is running or free RAM <3 GiB. `stop` uses only clean guest shutdown. `reset` requires the original Off, the exact checkpoint ID, backup hash, healthy storage and the recovery VM Off. It does not delete or merge any checkpoint.

After first boot, verify SSH authentication/host key, Nginx config and service, independent Windows HTTP 200 and exact bytes, static management IP, SSH and network config hashes. Create a unique harmless `/var/tmp/ticketsim-b5-marker-<uuid>` on the original only after confirming it was absent. Verify it exists. After approved stop/reset/start, verify the marker is absent and repeat the host/guest checks, including all four backup hashes, checkpoint identity, SSH config, firewall hash, management route, RAM/storage and no other VM changes. B5 PASS requires an evidence record with the exact `appliedCheckpointId`, marker absent, `http200Exact`, page SHA256, `sshAuthenticated`, backup hash, no other VM changed, final state `Running`, and the pinned SSH config/firewall hashes. Any failed or unknown check keeps the target quarantined. Do not delete, merge or consolidate the checkpoint automatically.
