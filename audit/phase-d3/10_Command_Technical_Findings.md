# D3-C1 Command Library technical findings — 2026-10-26

## Meaning of the audit

The 31 cards below were compared with upstream manuals or product documentation for their displayed syntax, named flags, example/output shape, relevant exit status, privilege, distro behavior, interpretation and safety. The URLs are **editorial evidence**, recorded again in each card's `review_evidence` field in `07_Command_Expert_Review.csv`. They do not automatically change D2 `source_verification`: **71 `SOURCE_VERIFIED`, 31 `PENDING`, 20 `INTERNAL_SOP_REQUIRED`**. No command was executed on a customer VM; all `lab_verification` values remain `PENDING`.

`AGENT_REVIEWED` means a documentation and effective-source pass, not expert or lab sign-off. Exact stdout depends on installed version, locale, permissions and the target host. The Library's `outputIsExcerpt` field marks snippets; it must not be read as a complete terminal transcript. All 31 are read-only probes except where a card explicitly states a different safety class; none is run by the TicketSim terminal.

## Important existing command families

Spot-check of the effective 71 `SOURCE_VERIFIED` cards covered the requested families `ss`, `ip`, `systemctl`, `journalctl`, `ssh`, `sshd`, `curl`, `dig`, `df`, `du`, `find`, `ps`, `top`, `free`, `lsblk`, `firewall-cmd`, `nmcli`, `docker`, `mtr`, and `tcpdump`. Their source links and `does_not_prove` fields remain in the D2 ledger and `07_Command_Expert_Review.csv`. `SOURCE_VERIFIED` is D2 source metadata, **not** a new whole-card approval. `mount` has no standalone card: the Library currently exposes `findmnt` and fstab/LVM reads. A future card would need a distinct read/change safety contract; this audit did not add one.

The D3-B firewalld distinction remains: default zone need not handle the interface/source actually carrying traffic. The `sshd -T | grep '^port '` card still warns that file-derived effective configuration does not prove the running daemon has loaded it. `ps %CPU` remains lifetime-based; `top`, `free`, `df/du`, `docker stats`, `mtr` and `tcpdump` each require the documented scope, time and source limitations. No new usage flags were added merely to increase example count.
